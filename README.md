# S’word Master — React 웹게임

현재 개발 소스는 **React + Vite + JavaScript + CSS**입니다. 시작 화면과 메뉴, 설정, 티어별 단어장, 브론즈 제1장 스토리와 단어 마법 전투, 브론즈 완료 후 해금되는 상점을 구현했습니다. 타이틀의 픽셀 던전·짙은 녹회색·금색 선택 표시를 이어갑니다.

v0.7에서는 자동 대사 진행·장면 애니메이션·전투 4곳과 퍼즐 3곳·오답 복습을 연결했습니다. [전투 배치, 수정 대사와 연출 정리](docs/bronze-combat-v0.7.md)를 참고하세요.

v0.8에서는 입구와 지하 통로를 분리하고, 작은 슬라임과 첫 전투 후 축제 마을로 들어갑니다. 표지판은 길 찾기 퍼즐로 표현하고, 그림 인형과의 전투에는 주민을 지킨다는 동기를 붙였습니다. [도입·전투 동기 수정](docs/story-v0.8.md), [이상 낙원 오마주와 이야기 평가](docs/story-homage-review.md).

v0.9에서는 첫 슬라임전에 **해독검** 스킬 모션을 추가했습니다. 정답 뒤 준비·돌진·베기·복귀, 오답 방어, 마지막 컷인과 종결 베기를 재생합니다. 효과음은 설정에서 끌 수 있고, 움직임 줄이기에서는 정적 결과로 표시합니다. [스킬 연출과 확인 방법](docs/slime-skill-v0.9.md).

## 실행

Node.js 20.19+ 또는 22.12 이상이 필요합니다. 이 폴더에서 실행합니다.

```sh
npm install
npm run dev
```

개발 주소: `http://127.0.0.1:8175/`. 종료는 터미널에서 Ctrl+C입니다.

배포용 파일 생성과 확인:

```sh
npm run build
npm run preview
```

미리보기 주소: `http://127.0.0.1:8176/`. `dist/`가 배포할 파일입니다. 학교에서 사용할 공개 주소는 아직 없습니다. 원본 소스는 Vite를 통해 실행하며, Python 서버로 원본 JSX를 직접 제공하지 않습니다.

## Cloudflare Workers 배포

`wrangler.jsonc`에서 Vite 빌드 결과인 `dist/`를 정적 자산으로 지정하고, React 앱의 탐색 요청을 `index.html`로 연결합니다. Vite 자산 경로는 `/`를 기준으로 생성해 하위 주소에서도 스크립트와 글꼴을 불러옵니다. `wrangler preview`에 필요한 빈 `previews` 블록도 포함합니다. 정적 자산과 호환성 날짜는 최상위에 설정합니다. [Cloudflare Previews 설정](https://developers.cloudflare.com/workers/previews/configuration/#wrangler-configuration-file).

Cloudflare의 저장소 빌드 설정은 다음과 같습니다.

- 루트 디렉터리: 이 저장소 루트
- 빌드 명령: `npm run build`
- 미리보기 배포 명령: `npx wrangler preview`
- Worker 이름: `sword-master` (`wrangler.jsonc`의 `name`과 일치)

Wrangler는 오류 로그와 같은 `4.157.0`으로 고정해 설치합니다. 로컬에서 Cloudflare 업로드 없이 빌드·배포 설정을 검사하려면 `npm run deploy:check`를 실행합니다. Cloudflare 계정 인증이 준비된 환경에서는 `npm run deploy:preview`로 빌드 후 미리보기를 배포할 수 있습니다. 기존 `npm run preview`는 Vite의 로컬 미리보기입니다.

## 파일 역할

- `src/main.jsx`: React 시작점과 StrictMode.
- `src/App.jsx`: 시작 화면과 메뉴 선택 상태, 키보드 이동, 티어 선택과 스토리 진입.
- `src/components/TierSelectDialog.jsx`: 5개 티어 표시와 제공된 스토리 선택.
- `src/components/StoryPlayer.jsx`, `StoryArt.jsx`: 대사 읽기, 장면 이동, 픽셀 배경과 캐릭터, 이야기 엔딩.
- `src/story.js`, `src/data/bronze-story.json`, `bronze-opening.json`, `bronze-direction.json`: 브론즈 9개 장면과 306줄, 원문·수정본 관리, 스토리 이동과 별도 감상 기록 저장.
- `src/story.css`: 티어 선택과 스토리 화면, 작은 화면과 글자 크기 설정 대응.
- `src/menuNavigation.js`: 창·탭 전환이나 배경 클릭 후에도 마지막 선택에서 키보드 조작을 이어가는 입력 처리.
- `src/components/MenuDialog.jsx`: 준비 중 안내창과 HTML dialog 동작.
- `src/components/TitleScene.jsx`: Canvas 애니메이션 연결. 컴포넌트가 사라지면 AbortController로 루프·이벤트를 정리합니다.
- `src/components/SettingsDialog.jsx`: 화면·연출 설정과 조작 안내. 즉시 반영, 전체 화면 전환, 기본값 복원, 키보드 이동과 초점 복귀.
- `src/components/VocabularyDialog.jsx`: 티어별 단어장, 누적·추가 범위 전환, 검색, 상세 설명과 페이지 이동.
- `src/vocabulary.js`, `src/data/vocabulary.json`: 원자료 1,000개 항목과 누적 티어·검색 처리.
- `src/settings.js`: 설정값 검증과 버전이 있는 브라우저 저장. 학습 기록과 별도의 키를 사용합니다.
- `src/shop.js`, `src/progression.js`, `src/components/ShopDialog.jsx`, `src/shop.css`: 코인·아이템, 전투 보상 정산, 브론즈 완료 해금과 타이틀 상점.
- `src/scene.js`: 384×288 픽셀 격자 위의 벽·문·바닥·용사·망토·횃불. 정적 배경은 한 번 그려 재사용하고, 작은 망토와 불빛만 갱신합니다. 큰 배경 이미지에 의존하지 않습니다.
- `styles.css`: 배치·글꼴·선택 메뉴의 3.2초 밝기 변화·작은 창 대응.
- `assets/`: 공개 글꼴과 이전 버전의 이미지 보관본. 현재 메인 화면은 글꼴만 불러오며 이전 배경 이미지는 배포 빌드에서 참조하지 않습니다.
- `public/licenses/`: 배포 파일에도 포함되는 글꼴 OFL 라이선스.
- `package-lock.json`: 실제 설치한 의존성 버전을 고정한 기록. 팀에서는 `npm ci`로 동일하게 설치할 수 있습니다.

## 구현 범위와 확인

타이틀의 ‘상점’은 브론즈 8개 전투·퍼즐을 직접 풀고 이야기 엔딩에 도달하면 해금됩니다. 일반 전투 20코인·보스 80코인에 실제 정답당 5코인을 더하며, 완료한 재도전도 보상을 줍니다. 퍼즐과 연출 감상에는 코인이 지급되지 않습니다. 집중의 렌즈(40코인)와 망토 3종(80·100·120코인)을 구매하고 장착할 수 있습니다. 렌즈는 문제마다 오답 보기 하나를 지웁니다. 코인·아이템·해금·지급 여부를 학습 기록과 함께 저장해 새로고침으로 중복 지급·소모되지 않게 합니다. [상점 규칙과 검증 결과](docs/title-shop.md).

‘게임 시작 → 브론즈’를 선택하면 석문이 열리고 용사가 자동으로 걸어 들어갑니다. 용사가 들어간 뒤 문이 닫히며, 총 약 3.4초의 입장 연출 후 던전 안에서 이야기를 시작합니다. 클릭·터치 또는 Esc로 연출을 건너뛸 수 있고, 움직임 줄이기·끄기는 짧은 정지 화면으로 연결합니다. 이어보기는 저장된 위치로 바로 이동합니다. [자동 입장과 도입 대사 변경](docs/dungeon-entry.md).

‘게임 시작 → 브론즈’에서 제1장 이야기를 자동 진행으로 감상하고, 단어 마법으로 관문을 해결합니다. 8개 구간의 출제 범위는 브론즈 64개와 복습 6문항입니다. 첫 슬라임전은 기존 네 단어를 순환 출제하며 체력 0%에서 끝납니다. 일찍 처치해 풀지 않은 단어에는 학습 기록을 부여하지 않습니다. 표지판·봉인·소품은 전투와 다른 복원 연출을 사용합니다. 이야기 위치와 응답을 같은 브라우저에 저장하고 타이틀의 ‘이어보기’로 돌아옵니다. 실버·골드·플래티넘·마스터 이야기는 준비 중입니다. 설정·단어장·오답 복습을 사용할 수 있고, 전투와 퍼즐의 연출만 감상할 수도 있습니다.

## 해독검 액티브 스킬과 몬스터 체력

모든 몬스터 위에 남은 체력을 백분율로 표시합니다. 첫 슬라임은 체력 100%에서 뜻 확인마다 기본 피해 20%를 받습니다. 3연속 정답이면 해독검을 한 번 충전하고, 버튼 클릭·터치 또는 Q 키로 피해 40%의 스킬을 사용합니다. 용사·기술명 컷인 0.8초와 베기·복귀 1.2초를 합쳐 총 2초입니다. 3연속 정답 후 해독검을 쓰면 바로 처치하고, 사용하지 않아도 최대 5문항이면 끝납니다.

충전된 스킬은 사용까지 보관하며 자동 진행도 사용 또는 수동 다음 문제를 기다립니다. 다른 전투는 기존 진행 규칙을 유지하고, 퍼즐에는 문항 수와 복원 진행을 표시합니다. [규칙·저장 호환·검증 기록](docs/active-decode.md).

## 루미페스타의 대사별 장면

루미페스타의 284개 대사에 14개 장소·81개 사건 구도를 연결했습니다. 환영 광장, 해골 상인의 가게, 풍선 거리, 표지판 갈림길, 장난의 골목, 직원용 뒷길, 대본 창고, 봉인된 문, 소품실, 결승 무대, 방송이 끝난 광장, 문 닫는 가게, 기록 확인실과 학교로 이어지는 풍경을 구분합니다.

대화 상대에 따라 구도가 바뀌고, 카메라·안내판·대본의 날짜·지워진 이름·찢어진 도장·변조된 영상·가면 조각은 해당 대사에서 확대해 보여 줍니다. 모모의 합류와 니아의 이동, 보스의 등장·파손·퇴장도 대사 순서를 따릅니다. 기존 대사·장면 ID·전투 규칙과 저장 위치는 유지합니다. [장면 구성과 확인 캡처](docs/festival-scenes.md).

React 19.3.1, React DOM 19.3.1, Vite 8.3.5, React 플러그인 6.2.1 설치와 배포 빌드가 통과했습니다. 개발 컴퓨터는 Node.js 26.8.1입니다.

React 배포 빌드의 실제 브라우저에서 방향키 순환·비활성 메뉴 건너뛰기·Tab·Enter·Esc·초점 복귀, 클릭으로 오답 복습 안내 열기와 돌아가기를 확인했습니다. 1366×768 및 360×480 창에서 메뉴에 접근할 수 있었고 가로 넘침은 없었습니다. 서로 다른 시점의 캡처로 횃불·망토·선택 표시가 움직이는지 확인했으며, 브라우저 콘솔 오류·경고는 없었습니다. 캡처는 `docs/screenshots/react-*.jpg`에 보관합니다.

플랫폼의 움직임 줄이기 설정에 따른 정지 화면과 숨겨진 탭에서의 일시 정지를 지원합니다. 실제 학교 크롬북·터치패드 하드웨어·학교 네트워크·메모리 사용량은 아직 검증하지 않았습니다.

[기존 이미지 생성 기록](docs/animation-assets.md). React 전환에서는 새 이미지를 생성하지 않았습니다. 이전 Flutter 격자 방식 설명은 당시 작업 기록이며, 현재는 Canvas 2D의 가로 띠 변형 방식입니다.

## 메인 화면 개편 — v0.4

[UI 개편 계획](docs/UI_REDESIGN_PLAN.md)의 시작 화면 방향을 적용했습니다. 좌측은 작은 두 줄 로고와 명확한 메뉴, 우측은 독립된 픽셀 던전 입구 장면으로 구성했습니다. 새 모험을 최상단 기본 선택으로 두고, 저장 기록이 없는 이어하기는 바로 아래 비활성 상태로 표시합니다.

[픽셀 장면과 확인 기록](docs/main-screen-v0.4.md). 새 이미지 생성 도구는 사용하지 않았으며, 벽·문·바닥·용사·망토·횃불을 코드로 구성했습니다. 예전 이미지 자산 기록은 이전 버전의 보관 자료입니다. 전투·학습 문제·결과 화면은 이번 변경에 포함하지 않았습니다.

## 설정 화면 — v0.5

타이틀의 설정 메뉴에서 화면·연출과 조작 안내를 엽니다. 글자 크기(보통·크게·아주 크게), 배경 움직임(기본·줄이기·끄기), 메뉴 선택 효과(천천히 밝아짐·고정)를 즉시 적용하고 같은 브라우저에 자동 저장합니다. 학습 진행 저장과는 별개입니다. 전체 화면은 브라우저가 허용할 때 전환하며 저장 대상이 아닙니다.

배경 움직임을 끄거나 기기의 움직임 줄이기가 켜져 있으면 Canvas 애니메이션을 멈춥니다. 기본값 복원은 화면 설정만 복원하며 다른 저장 데이터는 지우지 않습니다. 저장소를 사용할 수 없으면 이번 접속에서 설정을 유지하고 안내를 표시합니다. 음악·효과음과 전투 관련 설정은 해당 기능을 추가할 때 연결합니다.

`npm test`로 설정 저장·복구, 애니메이션 정리, 메뉴 포커스 복구, 단어 데이터와 티어·검색 테스트 22개를 실행합니다. [설정 화면 구현과 확인 기록](docs/settings-v0.5.md)을 참고하세요.

## 창 전환 후 키보드 입력 복구

기존에는 시작 메뉴 안에 초점이 있을 때만 방향키를 처리해, 창·탭을 옮기거나 배경을 클릭한 뒤 초점이 페이지로 빠지면 조작이 멈췄습니다. 이제 페이지 배경에서도 ↑·↓·Home·End를 누르면 마지막 선택부터 이동하며 메뉴에 초점을 돌려줍니다. Enter·Space도 배경에서 선택한 메뉴를 실행합니다. 설정이나 안내창이 열려 있을 때는 시작 메뉴 입력 처리를 해제하고, 다른 컨트롤의 입력·단축키·한글 조합 중 입력은 가로채지 않습니다.

Safari의 배포 빌드에서 배경 클릭, 다른 창과 탭으로 이동 후 복귀, 방향키 순환, Enter 실행을 확인했습니다. 설정 분류와 라디오 버튼의 방향키 조작, Esc 종료와 마지막 메뉴 초점 복귀도 확인했습니다. `npm test` 16개와 `npm run build`가 통과했습니다.

## 티어별 단어장

타이틀의 ‘단어장’에서 브론즈 64·실버 290·골드 741·플래티넘 969·마스터 1,000개의 누적 범위를 선택합니다. ‘누적 전체’와 ‘해당 티어 추가’ 범위를 전환하고 단어·뜻·유의어·반의어·출처를 검색할 수 있습니다. 항목을 펼치면 어휘 관계와 출처가 나타나며, 목록은 30개씩 표시합니다. 티어는 학습 범위이며 모두 열려 있습니다.

5개 원본 PDF의 모든 표를 추출해 마스터 범위와 행 단위로 대조했습니다. 같은 철자라도 뜻이 다른 항목은 구분하고 원문의 설명·상대어 표시를 유지합니다. [자료와 구현 확인 기록](docs/vocabulary.md).
