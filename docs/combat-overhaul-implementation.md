# S’word Master 전장 개편 구현 기록

## 전투 재생

- 카드별 준비·타격·효과 완성·복귀 시점을 3D와 Phaser 간편 화면이 공유한다. 전투 화면이 재생기와 타격 번호를 보관하므로 WebGL 오류 뒤에도 간편 화면에서 남은 타격을 이어서 표시한다.
- Kenney 기사 모델의 팔·다리·손목에 카드별 자세를 적용한다. 실제 손목과 칼끝 사이를 샘플링해 잔상을 그리며, 쌍격은 방향과 색이 다른 두 잔상으로 구분한다.
- 표시 체력, 피해·방어 숫자, 타격 정지, 피격 동작, 카메라와 소리는 타격 순번에 맞춰 재생한다. 적의 강타는 다음 행동 패턴을 따르고, 용사 사망 예고와 실제 피해가 같은 방어 계산을 사용한다.
- 일반 전투 기준 기본 베기 0.89초, 강공격 1.395초, 쌍격 1.36초, 노바 1.79초다. 강화와 처치는 해당 타격에 정지 시간이 추가된다.

## 연출과 설정

- 검광, 바닥 균열과 파편, 교차 검광, 파동 투사체, 노바 빛기둥과 충격파를 추가했다. 방어막, 회복 꽃잎, 강화 불씨, 약화 사슬, 집중 별빛, 흐름의 나선, 서약 문장과 왕관을 카드별 시점에 연결했다. 강화형에는 카드별 문양과 추가 충격을 사용한다.
- 검광 마스크와 폭발·연기 연속 프레임은 직접 생성한 자산이다. Pillow 환경에서 `python3 scripts/export_combat_textures.py`로 재생성할 수 있다. Kenney 원본의 CC0 표기는 기존 고지에서 확인할 수 있다.
- 높은 품질은 전투에서 선택적 발광과 높은 잔상·입자 예산을 사용한다. 낮은 품질은 발광 후처리를 끄고 잔상·입자·파편을 줄인다. 움직임 줄이기는 짧은 결과 표시를, 끄기는 즉시 결과 표시를 사용한다.
- 효과음은 Web Audio로 생성하며 브라우저 사용자 입력 뒤 재생한다. 기존 설정 저장 형식에 효과음 켜기·끄기와 0~100% 음량을 추가했다. 이전 설정은 켜짐과 60%로 초기화된다.

## 전투 카메라

- 기본 구도는 옆모습 대신 용사 뒤쪽 사선(3/4)이다. `src/game/three/battleCamera.js`가 화면 비율에 맞춰 두 캐릭터와 머리 위 표시 공간이 들어오는 거리를 계산한다. 가로로 긴 PC 전투 띠에서는 가로 시야각을 74°로 묶어 벽이 휘지 않게 하고, 카메라 거리만큼 안개를 뒤로 민다. 전투 장면은 뒷벽을 19칸, 바닥을 9줄로 늘려 비스듬한 화면에서도 끝이 보이지 않는다.
- `src/game/three/cameraDirector.js`가 재생 중인 연출 시간표를 보고 장면을 고르고, `BattleCamera.jsx`가 부드럽게 따라간다. 근접 베기는 접촉 지점을 당겨 보고, 강공격은 위에서 내려다보며, 원거리 기술은 어깨 너머로 돈다. 노바는 충전 중 용사 주위를 돌다가 폭발 순간 물러난다. 회복·방어는 정면 구도, 약화와 적의 방어·강화는 적 쪽으로 시선을 옮긴다. 적의 공격은 낮게, 강타 준비는 적 발치에서 올려다보며, 처치는 옆으로 돌아 무너지는 적을, 용사가 쓰러지면 용사를 비춘다.
- 카드 12종은 `src/game/cardMotions.js`의 `camera` 키를 따라 카드마다 다른 순서로 움직인다. 키는 카드의 동작 시점(준비·도약·타격·효과 완성) 이름으로 적고, 이웃한 키 사이는 기본 구도를 거치지 않고 곧장 넘어간다. 장면 정의는 `cameraDirector.js`의 `CARD_SHOTS`에 있다.
  - 기본 베기: 달려 나가는 용사를 따라가다 접촉 순간 옆에서 당겨 본다.
  - 균열 베기: 웅크린 용사를 아래에서 올려다보고, 도약을 따라 올라간 뒤 바닥을 내려찍는 순간 위에서 본다.
  - 쌍월: 올려 베기는 낮은 앞쪽에서, 내려 베기는 높은 뒤쪽에서 본다.
  - 잿빛 파동: 어깨 너머로 겨눴다가 검기를 따라 적 쪽으로 돈다.
  - 새벽의 낙인: 검을 든 용사를 올려다보다가 정적의 순간 좁은 렌즈로 멈추고, 터진 뒤 넓은 렌즈로 높이 물러난다.
  - 돌의 자세는 낮은 정면, 이슬의 숨은 고개를 들 때 위로 올라간다. 불씨 벼리기는 웅크릴 때 다가갔다가 펼 때 물러나고, 녹슨 봉인은 손 너머로 겨눴다가 적 쪽으로 다가간다.
  - 고요한 응시는 렌즈를 좁히며 물러나는 돌리 줌, 바람의 손은 회전을 따라 앞쪽으로 돈다. 불멸의 서약은 무릎 꿇을 때 내려다보다가 일어설 때 왕관까지 올려다본다.
- 타격 정지 동안에는 시간표가 멈추므로 카메라도 타격 구도에 머문다. 처치한 타격에서는 카드 카메라가 멈추고 처치 장면이 이어받는다.
- 좁은 렌즈 장면은 카메라가 바닥 앞끝(z=18)을 넘지 않는 만큼만 렌즈를 좁힌다. 세로로 긴 휴대폰 화면은 기본 구도부터 멀리 있어 돌리 줌·정적의 당김이 PC보다 약하다. 가로로 긴 PC 띠는 가로 시야각 상한 때문에 넓은 렌즈가 기본 렌즈와 같다.
- 장면은 시간표 안에서 들어가고 나와 연출이 끝나는 순간 기본 구도로 정확히 돌아온다. 타격 흔들림과 펀치 줌은 이 위치를 기준으로 더하며, 펀치 줌은 좁혀진 시야각에도 같은 비율로 적용한다. 대기 중에는 1° 정도의 느린 흔들림이 있고, 퀴즈를 푸는 동안·움직임 줄이기·끄기에서는 기본 구도에 고정한다. 용사 체력이 30% 이하이면 기본 구도를 조금 낮고 가깝게 잡는다. 틀린 답의 헛손질은 카메라를 움직이지 않는다.
- Phaser 간편 화면은 이번 카메라 변경의 대상이 아니다.

## 검증

- `npm test` 85개 통과. 새 타임라인과 GLB 칼끝, 타격 정지, 중복 방지, 쌍격 첫 타격 처치, 기존 저장·설정의 호환성을 확인했다.
- `npm run build` 통과. Vite의 대형 청크 경고가 표시된다.
- `npm run test:3d`에서 일반·강화 카드 24가지, 몬스터 12종의 다단 타격, 완전 방어와 처치, 품질·모션 설정, 탭 숨김과 복귀, 리사이즈 중 3D에서 간편 화면으로 이어지는 두 번째 타격을 확인했다.
- `npm run test:ui`에서 360px 화면과 큰 글자 설정, 학습·오답 복습, 간편 화면과 입체 화면 전환, 패배 결과 및 타이틀 복귀를 확인했다.
- `npm run test:journey`에서 브론즈 모험을 127단계로 완료했다. 퀴즈 도중 새로고침을 거쳐 33문제 정답과 브론즈 클리어, 서약 해금이 저장됐다.
- Chromium에서 쌍격의 준비음과 두 타격이 Web Audio 소리를 발생시키고, 음량 37%와 음소거가 다시 열어도 유지되는 것을 확인했다.
- 전투 카메라(2026-11-15): `npm test` 109개 통과(`test/battleCamera.test.js` 12개 포함: 모든 화면 비율에서 두 캐릭터가 화면 안에 있음, 연출 시작·끝의 정확한 복귀, 프레임 간 급격한 점프 없음, 퀴즈·움직임 줄이기에서 정지, 카메라가 바닥 위에 있음). `npm run build`, `test:3d`, `test:ui`, `test:journey` 통과. 실제 게임에서 대기 중 화면 가장자리 기준 약 6px 흔들림과 퀴즈 중 0px 이동을 확인했다. 장면별 연속 캡처는 `artifacts/camera-shots/`에 있다. 실제 기기 성능은 측정하지 않았다.
- 카드별 카메라(2026-11-15): `npm test` 112개 통과. 카메라 검사는 15개로, 카드 12종의 키가 실제 동작 시점과 장면 이름에 맞는지, 카드마다 움직임 순서가 다른지, 일반·강화·처치 연출에서 프레임 간 급격한 점프가 없는지(시야각 포함) 확인한다. 또 카드 연출 동안 용사의 실제 위치(heroPose)와 적이 몸 폭까지 네 가지 화면 비율 모두에서 화면 안에 있는지, 카드별 특징(균열 베기의 올려다봄→내려다봄, 쌍월의 교차, 파동 추적, 낙인의 좁은·넓은 렌즈, 응시의 돌리 줌, 서약의 내려다봄→올려다봄)을 확인한다. `npm run build`, `test:3d`, `test:ui`, `test:journey` 통과. 몸 폭을 넣은 검사에서 2단계 장면(적의 강타 준비·방어, 처치)도 기사 몸 일부를 자르던 문제가 드러나 함께 넓혔다. 카드별 키 시점 캡처는 `artifacts/card-camera/`에 있다(PC·휴대폰 시트 포함). 헤드리스 수동 진행 캡처라 실시간으로 따라가는 감속은 확인하지 않았고, 실제 기기 성능은 측정하지 않았다.
- `node scripts/capture-combat.mjs`로 기본 베기 8장, 쌍격 10장, 노바 9장을 `artifacts/combat-overhaul/`에 저장한다. 로컬 Chromium과 모바일 뷰포트로 확인했다. 실제 휴대폰·학교 PC의 목표 프레임은 측정이 필요하다.
