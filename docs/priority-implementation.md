# S’word Master 우선순위 구현 기록 — 2026-11-05

## 1. 조작·표시

구현: 티어 Enter → 시작 버튼 초점 → Enter 입장, 반복 키 방지와 방향키 경계 이동. 지도 선택은 아이콘 1.12배 확대·광륜으로 변경. 설명은 지도 위 안내 영역으로 이동하고 용사 발판을 분리. 전투 HUD는 캐릭터 영역 위에 별도 배치. 정답·오답은 큰 체크/X·초록/빨강·문구로 표시. 상태 배지는 이름·값·지속 조건과 hover/focus/click 상세 설명, Escape·바깥 클릭 닫기를 지원.

검증: 키보드 단위 검사 3개 통과. Safari 360×640 iframe에서 실제 AdventureDialog를 사용해 두 번의 Enter로 입장, 지도 설명·용사 분리, 약화 상세 클릭 열기와 Escape로 설명만 닫기, 카드 문제와 정답 강조·잠금 확인. 저장된 오답 해설 상태에서도 빨간 X·선택 답·정답·계속 버튼 배치를 확인. 이 장면은 메모리 상태만 사용하며 사용자 저장에 접근하지 않음.

## 2. 공격 2초

구현: 5종 각각 준비·타격·잔상·복귀. 검의 궤적은 전진 사선 베기, 균열은 내려찍기·균열·돌 파편, 쌍월은 교차 2회, 잿빛 파동은 이동하는 파동·폭발, 낙인은 회전 문양·빛기둥. 강화형은 추가 빛·입자. 피해를 각 타격 시점에 표시하고 종료 전 해설/계속 버튼을 숨김. 삼박의 종 추가 피해도 마지막 타격 표시와 합산. 진행 중 크기 변경은 장면 전체를 임시 확대/축소하고 종료 시 새 좌표를 확정하여 연출을 취소하지 않음.

검증: 순수 타임라인에서 0~2000ms 자세 복귀·8ms 간격 연속성·프레임 건너뛰기에도 타격 1회씩 전달을 확인. Safari 실제 Phaser Canvas에서 카드 12종 프레임 검사 통과. 실제 Scene.update를 2000ms 진행해 기본형·강화형 공격 5종의 600ms 시점 크기 변경 유지, 1200ms 진행 상태, 2000ms 종료·레이아웃 확정과 타격 횟수(1/1/2/1/1)를 확인. Safari 자동 제어 중 document.hidden=true로 실시간 루프가 일시 정지하는 경우가 있어, 이 프레임 진행 검증을 실시간 전체 재생/전체 전투 검증으로 표현하지 않음.

남은 실기 확인: 실제 활성 Safari에서 강화형·처치·창 크기 변경·이어하기를 포함하는 모든 전투 흐름의 연속 재생. 저장 후 이어하기의 규칙과 모든 티어 완주 자체는 reducer/저장 검사에 포함됨.

## 3. 몬스터·에셋

구현: 일반 6종 추가(유리날개 박쥐·비취 방울·별점 버섯·청동 딱정벌레·서리 등불·그늘 사냥개), 일반 총 9종. 강적 2종의 외형 분리. 공격·방어·강화·준비·숨 고르기의 자세/효과 구분. 같은 모험에서 미등장 몬스터를 먼저 선택하고 풀이 소진돼도 직전 적을 피함. 등장 기록과 타격별 피해 배열은 선택 필드이며 기존 저장 형식을 유지.

직접 정의한 픽셀 도형으로 투명 PNG 3종(용사 6자세·몬스터 12종×6프레임·상태 아이콘)을 만들고 실제 Phaser/배지에 연결. RGBA·완전 투명 픽셀·셀 크기와 빌드 포함 확인. 기존 이미지는 보존. 생성 소스와 제작 상태는 `assets/source/README.md`에 기록.

검증: 100개 시드에서 9종이 모두 나온 뒤 반복되는지 검사. 모든 몬스터의 모든 행동을 약화·힘·방어와 함께 저장/복원 후 실행하여 예고와 실제 결과 일치 검사. 이전 선택 필드가 없는 저장도 통과. Safari 작은 전투 장면에서 새 용사·박쥐·배지 아이콘이 실제 표시됨.

남음: Pixelorama `.pxo` 편집 원본과 시트의 공격 자세 추가 세분화. 앱 파일 대화상자 제어에서 반복한 `noWindowsAvailable`/시간 초과로 원본 저장을 완료하지 못했으며, 코드 제작 PNG를 Pixelorama 직접 제작 완료로 간주하지 않음.

## 사용자 수정 용사 원본 연결 — 2026-11-05

사용자가 `assets/concepts/young-warrior-pixel.png.pxo`에 눈·얼굴을 수정해서 저장한 원본을 제공했습니다. 이를 `scripts/export_hero.py`로 손실 없이 `assets/sprites/hero-young.png`에 내보내고 원본 SHA-256을 기록합니다. `npm run assets:hero`로 갱신하고 `npm run assets:check`로 원본 일치를 확인합니다. 원본은 수정하지 않습니다.

현재 용사 외형을 타이틀·입장·지도·전투에 연결했습니다. 한 자세 원본에서 망토·검을 든 팔·양다리를 나누어 호흡·보행·검의 준비/베기/복귀를 합성합니다. 공격 카드는 기존 2초 궤적과 타격 시점을 유지합니다. 손으로 그린 여러 자세가 아니며, 팔 뒤에 가려진 몸통은 보완 도형을 합성합니다. 이전 용사 시트는 보존합니다.

`/dev/hero-preview.html`의 실제 Canvas 비교에서 정지 자세 4,096픽셀 전부가 내보낸 원본과 일치했습니다. Safari 실제 Phaser 장면에서 새 용사의 대기·균열 베기 준비·던전 입장 표시를 확인하고, 공격 5종의 2000ms 진행·중간 크기 변경·타격 횟수·종료 검사를 통과했습니다. 숨김 탭의 시간을 직접 진행한 검사이며 실시간 전투 전체 재생 확인과 구분합니다. 현재 검사 수는 58개입니다.

앞서 기록된 “용사 Pixelorama 원본 없음”은 사용자 제공 파일로 해결되었습니다. 몬스터·아이콘의 별도 편집 원본과 수작업으로 세분화한 공격 자세는 여전히 남아 있습니다.

## 몬스터 공격 표시 수정 — 2026-11-06

원인: 피해 계산은 정상이나 적의 돌진 거리가 38px(강적 62px)로 고정되어 멀리 떨어진 용사에게 닿지 않았습니다. 여러 타격의 이동 tween도 190ms 간격으로 겹쳤습니다. 대부분의 2번 공격 프레임이 대기 프레임과 유사해 공격 여부가 더 불명확했습니다.

수정: 적 전용 연속 타임라인에서 준비 → 접근/투사체 → 타격 → 복귀를 진행합니다. 발톱·검·급강하·점프·돌진·내려찍기와 불꽃·서리·포자를 구분하며, 근접 공격은 두 캐릭터 사이 거리의 82%까지 접근합니다. 단타 1580ms, 2연타 1940ms, 3연타 2300ms이며 각 타격은 360ms 간격입니다. 체력과 피해/방어 숫자는 타격 콜백에 연결하고, 진행 중 행동을 표시한 뒤 다음 예고로 바꿉니다. 크기 변경·입력 잠금·치명타의 쓰러짐도 같은 타임라인을 사용합니다. 기존 저장/피해 규칙과 사용자 용사 원본은 변경하지 않았습니다.

검증: 단위 검사에서 12종의 실제 턴 종료 결과와 방어 0/5/100을 연결하고, 프레임 누락 시 타격 중복 방지·근접 도달·연타 중 복귀 방지·최종 자세·유한한 효과 좌표를 확인했습니다. 전체 61개 검사와 배포 빌드가 통과했습니다.

Safari의 실제 Phaser Scene에서 망령 단타·박쥐 2연타·사냥개 3연타의 공격/전부 방어 및 중간 크기 변경을 확인했습니다. 망령·사냥개는 치명타의 쓰러짐과 busy true→false 콜백까지 검사했습니다. 기존 용사 공격 5종의 2000ms·타격 횟수·크기 변경 검사도 통과했습니다. 실제 Battle UI에서 박쥐의 공격 4×2, 방어 6에 따라 HP 72→70이 반영됐습니다. 숨김 탭에서 일시 정지하는 Safari 특성 때문에 장면 타임라인을 직접 진행한 검사를 포함하며, 모든 몬스터의 실시간 전체 전투를 수동 완주한 것으로 간주하지 않습니다.
