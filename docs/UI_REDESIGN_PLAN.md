# S’word Master UI 개편 계획

작성: 2026-11-03. 상태: 제안. 이번 작업의 산출물은 실제 게임 화면에 근거한 개편 계획이다. React 구현은 화면별 다음 요청에서 진행한다. JavaScript 학습 연습이 아니라 영단어 학습용 게임 완성이 목적이다.

## 1. 현재 화면 진단

실제 구현된 시작 화면 캡처 `docs/screenshots/react-final.jpg`와 현재 프로젝트 지침을 확인했다. 다음은 화면 관찰에 따른 디자인 판단이며 사용자 테스트 결과는 아니다.

- 큰 영문 제목과 고밀도 배경·용사가 먼저 보이고, 학습을 시작할 메뉴는 상대적으로 약하다.
- 원근감·조명·질감이 강한 일러스트와 얇고 평평한 메뉴의 표현 차이가 커서 하나의 게임용 그래픽 체계로 느껴지기 어렵다.
- 장면이 한 장의 이미지에 합쳐져 있어 화면 크기에 따른 캐릭터 크기·위치를 독립적으로 조절하기 어렵다. 기존 망토 분리 효과는 타이틀용 임시 해법이다.
- 횃불·망토·선택 강조가 동시에 계속 움직인다. 어떤 요소에 주목해야 하는지 우선순위를 더 분명히 정할 필요가 있다.
- 현재 전투 화면은 구현되어 있지 않다. 기존 전투 시안을 실제 플레이 UI로 완성된 것처럼 평가하지 않는다.

목표는 ‘AI를 쓰지 않은 것처럼 보이기’라는 추상적 기준 대신, **같은 해상도·색·윤곽·정보 배치를 공유하는 실제 게임 화면**을 만드는 것이다.

## 3. 추천 시각 방향

**간결한 2D 픽셀 던전 + 읽기 쉬운 학습 패널**을 제안한다. 어두운 던전 분위기는 유지하되 캐릭터·배경·아이콘의 픽셀 크기와 윤곽을 통일한다.

- 1280×720을 배치 기준으로, 1366×768 및 작은 학교 화면에서 확인한다. 창이 작아지면 읽는 영역을 우선 보존한다.
- 시각 요소는 2~3px 기준 윤곽과 제한된 색상으로 통일한다. 실제 자산 해상도는 초안에서 비교한 뒤 확정한다.
- 배경은 저대비의 반복 가능한 방·바닥·벽 레이어로 만들고, 용사·적은 독립 스프라이트로 둔다. 기존 그림을 계속 잘라서 변형하는 구조를 확장하지 않는다.
- 색 초안: 바탕 #151919, 패널 #252C2B, 본문 #EEEBDD, 강조 #D3AE63, 위험 #BB6864. 실제 명도 대비는 구현 시 검사한다.
- 영문 로고는 더 작고 굵게 다듬는다. 한글 본문·문제에는 읽기 쉬운 고딕체를 사용한다. 픽셀 한글을 강제로 쓰지 않는다.
- 기본 글자 18~20px, 보기 20~22px, 문제 단어 30~36px를 출발점으로 한다. 긴 뜻·여러 줄 보기를 넣어 조정한다.
- 선택은 화살표·테두리·배경으로 표시하고, 사용자 요청인 3.2초의 느린 밝기 변화는 약하게 유지한다. 글자는 깜빡이지 않는다.
- 횃불과 망토 움직임은 타이틀의 작은 장면에 집중한다. 문제를 읽을 때는 눈에 띄는 입자와 큰 연출을 줄이고, 움직임 줄이기를 지원한다.

참고 작품은 배치와 정보 표현의 근거로 사용한다. 우리 캐릭터·로고·아이콘·배경은 별도 자산으로 준비한다.

## 4. 화면별 배치 제안

### 시작 화면

큰 포스터 같은 배경 비중을 줄이고, 작은 던전 입구 장면과 명확한 세로 메뉴로 구성한다. 로고 → 새 모험 → 보조 메뉴 순서로 보이게 한다.

- 좌측 약 40%: 로고, 짧은 부제, 메뉴. 오른쪽 약 60%: 독립된 용사와 던전 입구 장면.
- 새 모험을 기본 선택으로 둔다. 기록이 없는 이어하기는 비활성화하고 설명을 짧게 붙인다.
- 단어장·복습·설정은 같은 행 높이·간격·선택 표시를 공유한다.
- ‘한 단어, 한 걸음’ 등 보조 문구는 로고·메뉴와 경쟁하지 않도록 삭제 또는 축소하는 안을 초안에서 비교한다.

### 모험 준비

학습 범위(선생님의 티어)와 전투 난이도를 서로 다른 항목으로 둔다. 현재 선택 범위와 설명을 읽고 마지막에 ‘입장’을 누른다. 티어를 개인 승급으로 표현하지 않는다. 실제 자료가 준비되지 않았으면 단어 수·완료율을 가짜로 표시하지 않는다.

### 전투

전투 장면과 문제 영역의 역할을 고정한다. 용사는 장면의 약 35%, 적은 약 65% 위치에서 같은 바닥에 서도록 한다. 용사가 화면 끝에 밀리지 않고 전신이 보이게 한다.

```text
┌────────────────────────────────────────────────┐
│ 지하 1층 · 2번 방                    일시정지   │
├────────────────────────────────────────────────┤
│                         다음: 공격 6           │
│       용사 전신                  적            │
│       HP 30/40                HP 18/25          │
│                 같은 높이의 바닥               │
├────────────────────────────────────────────────┤
│ 공격       방어       회복 2회                  │
├────────────────────────────────────────────────┤
│ 뜻 고르기                                      │
│ abandon                                        │
│ [1] 버리다             [2] 보호하다             │
│ [3] 빌리다             [4] 기억하다             │
│ 잘 모르겠어요                        확인      │
└────────────────────────────────────────────────┘
```

모든 수치·단어는 배치 설명용 예시다. 화면 비율 초안은 상단 정보 6%, 전투 44%, 행동 8%, 문제 42%이며, 긴 보기와 작은 창으로 조정한다.

행동 선택 → 문제 → 정답/오답 설명 → 전투 결과의 흐름에서 같은 아래 패널의 내용을 바꾼다. 항상 모든 기능을 동시에 활성화하지 않는다. 선택과 확정은 구별하며, 1~4 숫자키·방향키·Enter·클릭을 모두 제공한다. 정답 설명은 고정 영역에 보여 주고 재입력으로 건너뛰지 않도록 한다. 구체적인 게임 효과는 기존 단계별 전투 구현 계획에서 연결한다.

### 결과·복습

게임 결과(승패·획득)와 학습 결과(실제 출제 수·정답률·틀린 단어/유형)를 구분한다. 결과의 주 행동은 ‘틀린 문제 복습’으로 잡되, 오답이 없으면 해당 상태를 안내한다. 복습은 큰 단어·뜻·관계와 다시 풀기 중심으로 단순하게 만든다.

## 5. 여러 입력으로 나누는 제작 순서

한 차수를 마치고 사용자 의견을 받은 뒤 다음 차수로 간다. 담당자와 날짜는 팀 합의 전까지 미정이다.

| 차수 | 작업 범위 | 산출물·확인 기준 |
| --- | --- | --- |
| 1 | 시각 규칙과 전투 흑백 배치 초안 | 색·글꼴·윤곽 규칙 한 장, 전투 배치 한 안. 캐릭터 전신·단어·긴 보기가 동시에 읽히는지 확인 |
| 2 | 시작 화면만 개편 | 승인한 규칙을 실제 React 메뉴에 적용. 기존 키보드·클릭·안내창 동작 유지 |
| 3 | 전투 화면 배치만 구현 | 독립 용사·적·체력·의도·학습 패널. 예시 데이터를 명시하고 실제 채점/전투 효과는 아직 연결하지 않음 |
| 4 | 모험 준비 화면 | 티어 범위와 전투 난도 분리, 입장 흐름과 뒤로 가기. 단어 데이터 연결 범위는 준비 상태에 맞춤 |
| 5 | 결과·복습 화면 배치 | 게임 승패와 학습 기록 구분, 오답 있음/없음 상태를 각각 표시 |
| 6 | 공통 UI 조정과 학교 확인 | 긴 문장, 키보드 전용, 터치패드, 작은 화면, 실제 크롬북, 애니메이션·가독성 점검 |

단어 추출·문제 풀이·전투 규칙·저장은 기존 단계별 기능 계획에 따라 별도로 연결한다. 이 UI 계획으로 기능 전체가 한꺼번에 구현되는 것은 아니다.

## 6. 구현과 완료 판단

기술은 현재 React + Vite + JavaScript + CSS를 유지한다. MenuButton, HealthBar, IntentBadge, QuestionPanel, AnswerOption 등 실제로 반복될 UI만 공통 컴포넌트로 만든다. React는 화면과 선택 상태를, Canvas는 필요한 장면 연출을 맡는다.

- 게임 전용 UI 라이브러리나 상태 관리 패키지는 화면 규모와 필요를 보고 결정한다.
- 먼저 배치와 글자 크기를 확인하고, 그 규칙에 맞는 캐릭터·배경 자산을 준비한다. 큰 완성 일러스트를 먼저 만들고 UI를 빈자리에 끼워 넣는 순서를 반복하지 않는다.
- 현재 브라우저 테스트 결과는 시작 화면에 한정된다. 새 전투 화면과 실제 학교 기기는 구현 후 별도 확인한다.
- 선택된 항목·현재 차례·적의 다음 행동·학습 질문을 설명 없이 찾을 수 있는지 친구의 사용 관찰로 확인한다. 아직 관찰을 수행한 것은 아니다.
- 색을 없애도 선택·정오답을 구분할 수 있어야 하며, 잘림·글자 크기·초점 이동·버튼 클릭을 실제 동작으로 확인한다.

바로 다음 작업의 제안: **1차 시각 규칙과 전투 흑백 배치 초안**. 사용자 의견을 반영해 다음 요청에서 시작한다.


## 실행 기록 — 메인 화면 v0.4

사용자가 메인 화면 개편을 직접 요청해 시작 화면부터 구현했다. 좌측 메뉴·우측 픽셀 던전 장면, 작은 로고, 새 모험 우선 순서와 약한 선택 강조를 적용했다. 정적 배경·캐릭터·망토·횃불은 코드의 별도 그리기 단계로 구성했다. 상세 기록은 `main-screen-v0.4.md`에 있다. 전투 화면·모험 준비·결과·복습 화면은 다음 차수로 남아 있다.
