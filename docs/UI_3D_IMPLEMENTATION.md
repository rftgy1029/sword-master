# S’word Master — UI·3D 구현 기록

작성일: 2026-11-12. v0.7.0에 [전체 UI·3D 계획](UI_3D_UPGRADE_PLAN.md)을 적용했다. 개발 환경의 브라우저 검증은 완료했으며, 실제 학교 컴퓨터·휴대폰의 성능 측정은 별도로 남아 있다.

## 적용한 화면

시작·티어 선택·던전 입장·경로·전투·보상·휴식·대장간·결과 화면에 Three.js 장면을 연결했다. 단어장·복습·설정·덱·유물·해설은 같은 색, 간격, 글자와 조작 상태를 공유하는 React UI로 정리했다.

- 짙은 녹색·아이보리·금색의 공통 스타일은 `src/styles/premium.css`에 있다.
- 공통 벡터 아이콘은 `src/components/ui/GameIcon.jsx`에서 카드·상태·장소에 사용한다.
- 체력·적 다음 행동은 장면 위에, 에너지·손패·퀴즈는 아래에 표시한다. 모바일 선택지는 세로로 배치하고, 손패는 가로로 스크롤한다.
- 카드 뒷면은 덱에서 실제 손패 위치로 이동한다. `src/game/cardDeal.js`의 브라우저 애니메이션으로 처리해 3D 전투에서 Phaser를 추가 로드하지 않는다.
- 3D 경로는 실제 8층 경로 데이터로 방·문·길·장소 모형을 구성한다. 방의 모형을 클릭하거나 아래의 키보드 접근 가능한 장소 버튼을 사용할 수 있다.

## 실제 3D 자산

`scripts/create_3d_assets.py`로 Blender에서 조형한 오리지널 모델을 GLB로 내보냈다. 그림을 평면에 붙인 방식이 아니라 메시·재질·부위별 관절 계층과 애니메이션을 가진 모델이다. 현재 모델은 스타일라이즈드 방향이며, 기존 일러스트의 붉은 망토·의상색·몬스터별 특징을 반영한다.

| 구분 | 구성 |
| --- | --- |
| 용사 | 얼굴·머리카락·의상·장갑·장화·검·망토. 대기·이동·공격·피격·방어·승리·쓰러짐 |
| 인간형 적 | 파수병·집행자·보스. 무기·갑옷·발광 눈·보스 왕관·망토와 7개 행동 클립 |
| 네 발·곤충·버섯 | 이끼 발톱·사냥개·딱정벌레·버섯. 관절 동작과 대기·이동·공격·피격·쓰러짐 |
| 비행·정령·슬라임 | 박쥐·불씨·서리·감시자·비취 방울. 날개·부유·불꽃·몸체 변형과 장면의 공격·피격 이동 합성 |
| 던전 | 석조 홀·서고·화로, 횃불·문·기둥·바닥·책장·모닥불·모루·상자 |

모델 13개 합계는 **2,716,684바이트**, 첫 용사·파수병은 합계 **707,452바이트**다. 별도 원격 모델 서비스나 디코더 다운로드는 필요하지 않다. 각 모델의 실제 애니메이션 이름·크기·메시 수는 `public/models/manifest.json`에 기록한다. 망토는 관절 애니메이션을 사용하며 물리 시뮬레이션은 사용하지 않는다.

재생성:

```sh
# Blender 4.3 이상 필요
npm run assets:models
```

동일한 관절·재질의 조각은 합쳐 draw call을 줄이고, 던전의 반복 석재와 책은 인스턴스로 렌더링한다. 이전 `.pxo`·PNG·2D 일러스트와 렌더러는 간편 화면에 사용할 수 있도록 보존한다.

## 전투와 게임 상태

Three.js 0.187.0과 React Three Fiber 9.8.2를 사용한다. `SceneView`가 3D와 간편 화면을 연결하고, `World.jsx`가 장면·모델·조명·효과를 구성한다.

- `CombatPlayback`은 연출 전용이다. 기존 reducer·문제·보상·티어 해금·저장 규칙은 유지했다.
- 카드 12종과 강화형은 기존 효과 색·타격 시점에 연결했다. 베기·내려찍기·쌍월·파동·낙인·방어석·회복·불씨·봉인·집중·바람·서약을 각각 표현한다.
- 몬스터의 공격·다단 공격·방어·강화·집중·대기를 구분한다.
- `onImpact`는 표시 체력을 갱신하며 실제 피해를 다시 적용하지 않는다. 같은 effect ID는 다시 재생하지 않는다.
- 프레임이 건너뛰면 그 사이의 모든 타격 표시를 한 번씩 전달한다. 치명타의 연출 완료와 기존 `END_TURN` 처리도 유지한다.
- 저장된 퀴즈·카드·에너지는 기존 저장 형식으로 이어진다. 3D 객체나 카메라 상태는 모험 저장에 추가하지 않는다.

## 그래픽 설정과 복구

기존 `sword-master.settings.v1`에 화면 방식과 그래픽 품질을 추가했다. 이전 설정에는 기본값을 채우며 글자·움직임·선택 효과는 유지한다.

| 설정 | 동작 |
| --- | --- |
| 자동·입체 화면 | 실제 3D 장면 사용 |
| 간편 화면 | 기존 2D 전투·입장·타이틀과 가벼운 배경 사용 |
| 자동 품질 | 작은 화면은 낮은 품질로 시작하고, 지속적인 느린 프레임에도 품질을 낮춤 |
| 낮음 | 그림자 끄기, 해상도 1배 이하, 30fps 갱신, 입자 16개 |
| 보통·높음 | 그림자·해상도·입자 수를 단계적으로 올림 |
| 움직임 줄이기·끄기 | 카메라와 지속 동작을 정지하고 공격 표시를 즉시 완료 |

모델 로드 실패·로딩 시간 초과·그래픽 컨텍스트 손실은 간편 화면으로 복구한다. 화면 방식을 다시 선택하면 3D를 재시도할 수 있다. 모험 화면을 열면 뒤의 타이틀 Canvas를 해제한다. 숨겨진 탭은 갱신을 멈추고 복귀 시 지난 숨김 시간을 공격에 더하지 않는다.

개발 환경의 보스 예제에서 낮은 품질은 92 draw call·77,514 렌더링 삼각형으로 관찰했다. 이 수치는 해당 장면의 한 프레임이며, 모든 장면의 최대값이나 실제 휴대폰의 프레임 성능을 의미하지 않는다. PC 60fps·모바일 30fps 목표는 실제 대상 기기에서 추가 측정해야 한다.

## 확인 방법

```sh
npm run dev
npm test
npm run build
```

브라우저 검증은 개발 서버를 실행한 상태에서 별도 터미널로 실행한다. 처음에는 `npx playwright install chromium`으로 테스트 브라우저를 준비한다. 이미 설치된 Chromium은 `CHROMIUM_PATH`로 지정할 수 있다.

```sh
npm run test:3d
npm run test:ui
npm run test:journey
# 애니메이션을 즉시 완료하는 모드로도 전체 모험을 확인
BROWSER_MOTION=off npm run test:journey
```

검증 캡처와 마지막 모험 상태는 Git에서 제외한 `artifacts/`에 생성한다. `BROWSER_BASE_URL`로 다른 로컬 서버 주소를 지정할 수 있다.

- `/dev/three-preview.html`: 저장 기록 없이 몬스터 12종·카드 12종과 강화형·품질·카메라 회전·2D 전환을 확인한다.
- `/dev/animation-preview.html`: 보존한 Phaser 장면을 확인한다.
- 자동 검사는 기존 규칙과 저장 호환 외에 GLB·재질·애니메이션·파일 크기·타격 누락·연출 중복·움직임 끄기·취소·품질 제한을 검사한다.
- 자동 검사 **76개**가 통과했다. GLB를 실제 로드해 준비 자세와 타격 자세 사이에 검을 든 관절이 회전하는지도 검사한다. 배포 빌드와 보관 Pixelorama 원본 일치 검사도 통과했다.
- Chromium WebGL에서 몬스터 12종의 다단 타격, 카드 12종의 타격 횟수와 강화형 12종의 추가 효과를 확인했다. 실제 검 관절 동작, 연출 중 화면 크기 변경, 움직임 끄기, 품질 낮추기, 카메라 회전, 컨텍스트 손실 후 2D 복구도 통과했다.
- 실제 UI에서 새 모험부터 **8층 보스·승리 결과·해금**까지 진행했다. 127회 동작·33문제 정답으로 완료한 기록은 `artifacts/sword-journey-result.json`에 남긴다. 기본 움직임과 움직임 끄기에서 모험 흐름을 확인했다.
- 1440×900·1366×768 PC 화면과 390×844·360px 모바일 화면에서 확인했다. 최대 글자 크기의 세로 선택지·모바일 터치 오답 기록·약점 복습 완료·Escape 초점 복귀·단어 검색·설정 저장·2D/3D 재전환이 동작한다.
- 3D 경로의 모든 방이 PC·모바일 화면 안에 들어오는지 확인했다. 방을 직접 클릭하면 해당 실제 경로를 선택한다. 대장간 카드·유물 강화와 구입은 기존 비용·골드·저장에 반영된다.
- 별도 테스트 저장에서 체력 1인 상황을 만들고 기본 움직임으로 턴을 종료했다. 적 치명타 연출이 끝나면 체력 0·패배 결과를 한 번 확정하고 타이틀로 돌아왔다.
- 배포 빌드의 시작 → 입장 → 지도 → 전투 → 퀴즈를 Chromium WebGL에서 확인했다. 활성 Canvas는 하나였고, 브라우저 오류와 모델 요청 실패는 없었다. GLB 13개의 응답 크기·헤더도 내보낸 목록과 일치했다.
