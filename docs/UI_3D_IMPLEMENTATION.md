# S’word Master — UI·3D 구현 기록

작성일: 2026-11-12. v0.7.0에 [전체 UI·3D 계획](UI_3D_UPGRADE_PLAN.md)을 적용했다. 개발 환경의 브라우저 검증은 완료했으며, 실제 학교 컴퓨터·휴대폰의 성능 측정은 별도로 남아 있다.

## 적용한 화면

시작·티어 선택·던전 입장·경로·전투·보상·휴식·대장간·결과 화면에 Three.js 장면을 연결했다. 단어장·복습·설정·덱·유물·해설은 같은 색, 간격, 글자와 조작 상태를 공유하는 React UI로 정리했다.

- 짙은 녹색·아이보리·금색의 공통 스타일은 `src/styles/premium.css`에 있다.
- 공통 벡터 아이콘은 `src/components/ui/GameIcon.jsx`에서 카드·상태·장소에 사용한다.
- 체력·적 다음 행동은 장면 위에, 에너지·손패·퀴즈는 아래에 표시한다. 모바일 선택지는 세로로 배치하고, 손패는 가로로 스크롤한다.
- 카드 뒷면은 덱에서 실제 손패 위치로 이동한다. `src/game/cardDeal.js`의 브라우저 애니메이션으로 처리해 3D 전투에서 Phaser를 추가 로드하지 않는다.
- 3D 경로는 실제 8층 경로 데이터로 방·문·길·장소 모형을 구성한다. 방의 모형을 클릭하거나 아래의 키보드 접근 가능한 장소 버튼을 사용할 수 있다.

## 타이틀과 화면 디자인 (2026-11-13)

AI가 만든 웹사이트처럼 보이던 화면을, 가장 개성 있는 요소인 Kenney 기사에 맞춰 다시 정리했다.

- **타이틀:** 3D 장면을 화면 전체 배경으로 깔고, 나무 테두리의 두툼한 패널 메뉴를 그 위에 올렸다. 넓은 화면은 메뉴가 왼쪽, 세로 화면은 아래쪽이며 카메라 구도가 메뉴를 피한다.
- **로고:** `S’WORD`의 아포스트로피를 작은 픽셀 칼로 바꿔 "S + word = sword" 말장난을 보여 준다(`src/components/ui/SwordLogo.jsx`).
- **단어로 고르기:** 메뉴마다 영어 단어(start·continue·words·review·settings)가 붙어 있고, 그 단어를 치면 기사가 칼을 휘두른 뒤 메뉴가 열린다. 클릭·방향키·Enter도 그대로 쓸 수 있다. 규칙은 `src/titleWords.js`, 검사는 `test/titleWords.test.js`.
- **기사 반응:** 메뉴를 고르는 동안 기사가 반응한다(새 모험: 칼 세우기, 이어하기: 걷기, 오답 복습: 막기 자세).
- **색:** '황혼'에 맞춰 3D 장면에 주황 노을빛과 보랏빛 하늘 조명을 넣고, UI 색도 거기서 뽑았다(`src/styles/dusk.css`, `World.jsx`의 `DUSK`). 녹색·금색 테두리 대신 짙은 자주색 패널, 나무 머리띠, 주황 버튼을 쓴다.
- **글꼴:** 한글 픽셀 글꼴 Galmuri(OFL, `assets/fonts/`)로 바꾸고 영문 세리프 제목을 없앴다.
- **문구:** 영문 라벨(WORDS BECOME…, CHAPTER I, 대화창의 S’WORD MASTER / …), ↵ 아이콘, 다이아몬드 기호, 하단 안내 문구를 지웠다. 설명은 게임 세계의 말투로 바꿨다(예: "저장된 기록 없음" → "아직 아무도 이 문을 지나지 않았다").

## 실제 3D 자산

몬스터 12종은 `scripts/create_3d_assets.py`로 Blender에서 조형한 오리지널 모델이고, 용사는 Kenney의 CC0 팩을 변환한 모델이다. 모두 그림을 평면에 붙인 방식이 아니라 메시·재질·관절과 애니메이션을 가진 GLB다.

용사(2026-11-13): Kenney **Mini Characters 2.0**(CC0)의 기사(`character-knight`)에 같은 팩의 검(`weapon-sword`)을 쥐여 `scripts/import_kenney_hero.py`로 변환한다. 원본은 `assets/kenney/mini-characters/`에 있고, 라이선스 고지는 `public/licenses/Kenney-Mini-Characters-CC0.txt`다. 뼈대가 있는 스킨 모델이며 뼈 이름을 `arm_right` 등 게임이 찾는 이름으로 바꾼다. 팩의 동작 32개 중 대기·이동·피격(`fall`)·쓰러짐(`die`)·방어(`holding-both`)는 그대로 쓰고, 공격은 주먹질 동작을 검에 맞게 다시 구워 타격 시점을 게임(동작의 50%)에 맞췄다. 회복·집중 카드와 승리 화면의 `victory`는 검을 똑바로 세운 자세다. 직접 조형했던 이전 용사 `hero()`는 `create_3d_assets.py`에 남아 있으며 `-- hero`를 명시할 때만 되돌린다.

던전(2026-11-13): 바닥·벽·출입구·기둥과 소품은 Kenney **Mini Dungeon 2.0**(CC0) 부품이다. `scripts/build_kenney_dungeon.py`가 `assets/kenney/mini-dungeon/`의 부품 26개를 색상표 텍스처 한 장과 함께 `public/models/dungeon-kit.glb` 하나(약 300KB)로 묶고, `src/game/three/kenneyDungeon.js`가 장소(석조 홀·서고·화로)와 장면(전투·타이틀·입장·보상 등)에 맞춰 배치한다. 부품 1칸은 장면에서 2.5단위로, 키 2.0인 용사에 맞춘 비율이다. 같은 부품은 인스턴스로 한 번에 그리고, 원래 색은 이 장면의 조명에서 거의 흰색으로 보여 녹회색(`KIT_TINT`)을 곱한다. 타이틀은 출입구에 닫힌 창살 문을, 보상 장면은 Kenney 상자와 동전·열쇠를 둔다. 횃불·서고의 책장·화로·바닥 문양은 이전처럼 이 게임에서 만든 장식이고, 던전 경로 지도는 기존 모형을 유지한다. 라이선스 고지는 `public/licenses/Kenney-Mini-Dungeon-CC0.txt`다.

게임에서는 모든 액터에 툰 명암·뒷면 외곽선·테두리 빛을 적용한다(`src/game/three/toon.js`). 외곽선은 스킨 모델에도 그리고, 각진 모델에서 선이 끊기지 않게 같은 위치의 법선을 평균해 쓴다. 빛나거나 반투명한 부위, 아주 작은 부위, 재질 이름이 ` detail`로 끝나는 얼굴 세부에는 외곽선을 붙이지 않는다.

| 구분 | 구성 |
| --- | --- |
| 용사 | Kenney Mini Characters 기사와 검(CC0), 키 2.0. 스킨 메시 2개·색상표 텍스처 1장. 대기·이동·공격·피격·방어·승리·쓰러짐 |
| 인간형 적 | 파수병·집행자·보스. 무기·갑옷·발광 눈·보스 왕관·망토와 7개 행동 클립 |
| 네 발·곤충·버섯 | 이끼 발톱·사냥개·딱정벌레·버섯. 관절 동작과 대기·이동·공격·피격·쓰러짐 |
| 비행·정령·슬라임 | 박쥐·불씨·서리·감시자·비취 방울. 날개·부유·불꽃·몸체 변형과 장면의 공격·피격 이동 합성 |
| 던전 | Kenney Mini Dungeon(CC0)의 바닥·벽·출입구·기둥·깃발·통·항아리·탁자·상자·창살 문과 이 게임의 횃불·책장·화로·바닥 문양. 석조 홀·서고·화로 세 장소 |

모델 13개 합계는 **2,435,988바이트**, 첫 용사·파수병은 합계 **426,756바이트**다. 별도 원격 모델 서비스나 디코더 다운로드는 필요하지 않다. 각 모델의 실제 애니메이션 이름·크기·메시 수는 `public/models/manifest.json`에 기록한다. 보스의 망토는 관절 애니메이션을 사용하며 물리 시뮬레이션은 사용하지 않는다.

재생성:

```sh
# Blender 4.3 이상 필요
npm run assets:models   # 몬스터 12종 (manifest의 용사 항목은 유지)
npm run assets:hero3d   # Kenney 기사 -> 용사
npm run assets:dungeon  # Kenney Mini Dungeon 부품 -> public/models/dungeon-kit.glb
# 특정 몬스터만: blender --background --threads 2 --python scripts/create_3d_assets.py -- sentinel boss
# 다른 Kenney 캐릭터: character-<이름>.glb를 assets/kenney/mini-characters/에 넣고 npm run assets:hero3d -- -- <이름>
```

두 스크립트는 GLB와 함께 Blender에서 열어 볼 수 있는 장면을 `assets/models/<이름>.blend`로 저장한다. 관절(용사는 뼈대)·재질·7개 동작(NLA 트랙)이 들어 있다. 원본은 스크립트이므로 `.blend`를 Blender에서 고쳐도 게임에는 반영되지 않고, 스크립트를 다시 실행하면 덮어쓴다. Blender UI 언어와 관계없이 같은 이름의 데이터를 만들도록 데이터 이름 번역을 끄고 실행한다.

동일한 관절·재질의 조각은 합쳐 draw call을 줄이고, 던전의 반복 석재와 책은 인스턴스로 렌더링한다. 이전 `.pxo`·PNG·2D 일러스트와 렌더러는 간편 화면에 사용할 수 있도록 보존한다.

## 전투와 게임 상태

Three.js 0.187.0과 React Three Fiber 9.8.2를 사용한다. `SceneView`가 3D와 간편 화면을 연결하고, `World.jsx`가 장면·모델·조명·효과를 구성한다.

- `CombatPlayback`은 연출 전용이다. 기존 reducer·문제·보상·티어 해금·저장 규칙은 유지했다.
- 카드 12종과 강화형은 기존 효과 색·타격 시점에 연결했다. 베기·내려찍기·쌍월·파동·낙인·방어석·회복·불씨·봉인·집중·바람·서약을 각각 표현한다.
- 몬스터의 공격·다단 공격·방어·강화·집중·대기를 구분한다.
- `onImpact`는 표시 체력을 갱신하며 실제 피해를 다시 적용하지 않는다. 같은 effect ID는 다시 재생하지 않는다.
- 프레임이 건너뛰면 그 사이의 모든 타격 표시를 한 번씩 전달한다. 치명타의 연출 완료와 기존 `END_TURN` 처리도 유지한다.
- 저장된 퀴즈·카드·에너지는 기존 저장 형식으로 이어진다. 3D 객체나 카메라 상태는 모험 저장에 추가하지 않는다.

## 그래픽 설정과 복구

기존 `sword-master.settings.v1`에 화면 방식과 그래픽 품질을 추가했다. 이전 설정에는 기본값을 채우며 글자·움직임·선택 효과는 유지한다.

| 설정 | 동작 |
| --- | --- |
| 자동·입체 화면 | 실제 3D 장면 사용 |
| 간편 화면 | 기존 2D 전투·입장·타이틀과 가벼운 배경 사용 |
| 자동 품질 | 작은 화면은 낮은 품질로 시작하고, 지속적인 느린 프레임에도 품질을 낮춤 |
| 낮음 | 그림자 끄기, 해상도 1배 이하, 30fps 갱신, 입자 16개 |
| 보통·높음 | 그림자·해상도·입자 수를 단계적으로 올림 |
| 움직임 줄이기·끄기 | 카메라와 지속 동작을 정지하고 공격 표시를 즉시 완료 |

모델 로드 실패·로딩 시간 초과·그래픽 컨텍스트 손실은 간편 화면으로 복구한다. 화면 방식을 다시 선택하면 3D를 재시도할 수 있다. 모험 화면을 열면 뒤의 타이틀 Canvas를 해제한다. 숨겨진 탭은 갱신을 멈추고 복귀 시 지난 숨김 시간을 공격에 더하지 않는다.

개발 환경의 보스 예제에서 낮은 품질은 92 draw call·77,514 렌더링 삼각형으로 관찰했다. 툰 외곽선을 적용한 뒤 같은 검사(`npm run test:3d`)에서는 149 draw call·99,020 삼각형이었고, 용사를 메시 2개짜리 Kenney 모델로 바꾼 뒤에는 95 draw call·77,144 삼각형이었다. 던전을 Kenney 부품의 인스턴스로 바꾼 뒤에는 103 draw call·31,022 삼각형이다. 학교 컴퓨터에서 느리면 낮은 품질에서 외곽선을 끄는 방안을 검토한다. 이 수치는 해당 장면의 한 프레임이며, 모든 장면의 최대값이나 실제 휴대폰의 프레임 성능을 의미하지 않는다. PC 60fps·모바일 30fps 목표는 실제 대상 기기에서 추가 측정해야 한다.

## 확인 방법

```sh
npm run dev
npm test
npm run build
```

브라우저 검증은 개발 서버를 실행한 상태에서 별도 터미널로 실행한다. 처음에는 `npx playwright install chromium`으로 테스트 브라우저를 준비한다. 이미 설치된 Chromium은 `CHROMIUM_PATH`로 지정할 수 있다.

```sh
npm run test:3d
npm run test:ui
npm run test:journey
# 애니메이션을 즉시 완료하는 모드로도 전체 모험을 확인
BROWSER_MOTION=off npm run test:journey
```

검증 캡처와 마지막 모험 상태는 Git에서 제외한 `artifacts/`에 생성한다. `BROWSER_BASE_URL`로 다른 로컬 서버 주소를 지정할 수 있다.

- `/dev/three-preview.html`: 저장 기록 없이 몬스터 12종·카드 12종과 강화형·품질·카메라 회전·2D 전환을 확인한다.
- `/dev/animation-preview.html`: 보존한 Phaser 장면을 확인한다.
- 자동 검사는 기존 규칙과 저장 호환 외에 GLB·재질·애니메이션·파일 크기·타격 누락·연출 중복·움직임 끄기·취소·품질 제한을 검사한다.
- 자동 검사 **76개**가 통과했다. GLB를 실제 로드해 준비 자세와 타격 자세 사이에 검을 든 관절이 회전하는지도 검사한다. 배포 빌드와 보관 Pixelorama 원본 일치 검사도 통과했다.
- Chromium WebGL에서 몬스터 12종의 다단 타격, 카드 12종의 타격 횟수와 강화형 12종의 추가 효과를 확인했다. 실제 검 관절 동작, 연출 중 화면 크기 변경, 움직임 끄기, 품질 낮추기, 카메라 회전, 컨텍스트 손실 후 2D 복구도 통과했다.
- 실제 UI에서 새 모험부터 **8층 보스·승리 결과·해금**까지 진행했다. 127회 동작·33문제 정답으로 완료한 기록은 `artifacts/sword-journey-result.json`에 남긴다. 기본 움직임과 움직임 끄기에서 모험 흐름을 확인했다.
- 1440×900·1366×768 PC 화면과 390×844·360px 모바일 화면에서 확인했다. 최대 글자 크기의 세로 선택지·모바일 터치 오답 기록·약점 복습 완료·Escape 초점 복귀·단어 검색·설정 저장·2D/3D 재전환이 동작한다.
- 3D 경로의 모든 방이 PC·모바일 화면 안에 들어오는지 확인했다. 방을 직접 클릭하면 해당 실제 경로를 선택한다. 대장간 카드·유물 강화와 구입은 기존 비용·골드·저장에 반영된다.
- 별도 테스트 저장에서 체력 1인 상황을 만들고 기본 움직임으로 턴을 종료했다. 적 치명타 연출이 끝나면 체력 0·패배 결과를 한 번 확정하고 타이틀로 돌아왔다.
- 배포 빌드의 시작 → 입장 → 지도 → 전투 → 퀴즈를 Chromium WebGL에서 확인했다. 활성 Canvas는 하나였고, 브라우저 오류와 모델 요청 실패는 없었다. GLB 13개의 응답 크기·헤더도 내보낸 목록과 일치했다.
