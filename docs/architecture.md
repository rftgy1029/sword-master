# 구조와 확장 방향

## 데이터 흐름

```text
data/words.ts ──→ Quiz ── 정답 보상 ──→ Battle ←── data/units.ts, stages.ts
                  ↑                       ↑
                  └──────── app.ts ────────┘
                         ↑       ↓
                  버튼·키보드   view.ts / renderer.ts
```

- `Battle`은 소환 비용, 생산, 전투, 기지 체력, 승패를 계산합니다. DOM·Canvas·네트워크를 참조하지 않습니다.
- `Quiz`는 문제, 선택지, 정답 보상, 콤보, 최근 단어, 복습 예약을 관리합니다. 전투와 직접 연결되지 않습니다.
- `app.ts`는 실행 중에만 답변을 허용하고, 퀴즈가 반환한 보상을 전투 에너지에 더합니다. 오답은 0, 이미 답한 문제는 `null`을 반환해 중복 지급을 막습니다.
- `view.ts`는 DOM 화면을 갱신하고 `renderer.ts`는 전투 상태를 받아 전장을 그립니다. 그리기 과정에서 전투 상태를 바꾸지 않습니다.
- 앱 종료·개발 중 코드 갱신 시에는 애니메이션과 이벤트 구독을 해제합니다.

## 상태 전환

`intro → running ↔ paused → won/lost/complete`

- `won`: 다음 스테이지로 진행하며 에너지·기지 체력·전투 유닛을 초기화합니다. 학습 기록은 유지합니다.
- `lost`: 같은 스테이지를 재도전하며 전투를 초기화합니다. 학습 기록은 유지합니다.
- `complete`: 전체 원정을 다시 시작하면 학습 기록까지 초기화합니다.
- `처음부터`: 현재 난이도로 첫 화면에 돌아가며 학습 기록을 초기화합니다.
- 일시정지 중에는 전투와 퀴즈 피드백 타이머가 함께 멈춥니다.

## 향후 기능을 붙일 위치

| 작업 | 시작할 위치 |
| --- | --- |
| 학교 단어장 도입 | `src/data/words.ts`, 이후 단어장 API 어댑터 |
| 난이도·스테이지 추가 | `src/data/stages.ts`와 난이도 선택 UI |
| 유닛 추가 | `src/data/units.ts`, 카드 UI, 렌더러 (현재 카드는 3개로 구성) |
| 보상·성장 조정 | `src/game/rules.ts`, 성장 모델 추가 |
| React 메뉴 | `src/ui/` 역할을 React 컴포넌트로 교체 |
| Phaser 전투 화면 | `src/game/renderer.ts`를 Phaser Scene으로 교체 |
| 계정·온라인 저장 | 별도 인증·API·저장소 모듈을 추가하고 `app.ts`에서 연결 |

현재 데이터는 플레이 테스트용입니다. 학교 공식 단어장과 연동되어 있지 않습니다.
현재 전투와 퀴즈 판정은 모두 클라이언트에 있습니다. 계정 재화·랭킹을 도입하면 서버 검증을 추가해야 합니다.
